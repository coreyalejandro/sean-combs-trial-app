# Shared changes requested by Builder 1 (Days 1 to 7)

None of these block Days 1 to 7: each has a local stand-in in `src/viz/day-01/kit/`. They would help every builder.

1. **`useQuietMotion()` crashes under jsdom.** `src/lib/viz/motion.ts` calls `window.matchMedia` unguarded, and jsdom has none, so any day whose client component uses the hook fails the shared `tests/unit/registry.test.tsx`. Request: guard it (`typeof window.matchMedia === 'function'`), or add a `matchMedia` stub in a vitest setup file. Stand-in: `kit/useQuiet.ts` (same contract, guarded).
2. **Sources from other days and from `additions.json` have nowhere to be listed.** The page test requires every `data-source-ids` id to resolve to `#source-<id>` on the page, but `SourcesPanel` lists only the day's own sources. Days 1 to 7 cite other days' records (Day 7 uses Day 15's bank records; Day 6 uses Days 1, 9 and 11) and added sources (city coordinates). Request: let `DayShell`/`SourcesPanel` take an optional `extraSources` list (or export a shared `ExtraSources` component), numbered after the day's own. Stand-in: `kit/Parts.tsx` `ExtraSources` (lettered a, b, c inside the figure) and `kit/refs.ts` `buildIndex`.
3. **Statements have no per-item sources.** `key_points`, `exhibits` and `legal_events` carry no source ids, so a picture that draws one of them can only cite outlets named in its text, sources whose headline names the same person, or the whole day. `kit/refs.ts` `findFact` does that, in that order, and caps confidence at "medium" ("low" when the day lists it as single-sourced). A `source` field on those items in the data would make this exact.
4. **Promote the kit.** `kit/refs.ts` (find a statement or figure by what it says; resolve and number sources; read years and months from text) and `kit/Parts.tsx` (`RefMarks`, `Sourced`, `Calculated`, `RowsTable`, `ExtraSources`) are general; moving them to `src/lib/viz/` and `src/components/shell/` would let other builders reuse them.
5. **Registry test allows one table only.** `tests/unit/registry.test.tsx` uses `getByRole('table')`, so a picture plus text version may hold exactly one `<table>`. Days 1 to 7 comply (one table per text version, pictures use grids and lists); noting it for other builders.
